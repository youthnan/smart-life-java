# 热点 Key 扩展方案（可选）

本文件记录生产级可选项，仅在压测证明单分片 Redis 已成为瓶颈时启用。

## 方案 1：热点店铺读副本扩展

- 入口仍走 `ShopServiceImpl.queryById`，优先命中 Caffeine。
- L2 读取可切到 Redis 只读副本（读写分离），降低主库压力。
- 风险：复制延迟导致短暂旧值，需要结合更新路径删除策略。

## 方案 2：按店铺 ID 做 Key 副本分片

- 对极热 ID 写入多份副本 key（如 `cache:shop:{id}:r0..rN`），读取随机命中。
- 更新时需要同时删除全部副本，适合极少量超热点 key。
- 风险：写放大与失效复杂度提升，不建议默认开启。

## 方案 3：秒杀 Lua 职责拆分

- 当 `seckill.lua` 逻辑继续膨胀时，可拆为「校验脚本 + 入队脚本」并保留原子边界。
- 配合 Stream 消费端幂等（唯一索引 / 业务去重）降低脚本复杂度。

## 启用前检查

1. 压测确认 Redis CPU 或网络是主要瓶颈。  
2. 已开启 Kafka 跨节点缓存失效，且监控可观测（命中率、延迟、错误率）。  
3. 可回滚方案准备就绪（开关 + 文档 + 演练）。
